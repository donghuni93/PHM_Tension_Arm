# 07 모델링: 시계열 분류 방법과 후보 모델

← [[06_특징선택]] · [[00_지도]] · 다음 [[08_평가_임계값]]

## 한 줄 정의
이 과제는 시계열 **예측**이 아니라 **분류**(2초 50,000점 → 정상 0 / 고장 1)다. 주력 경로는 시계열 → 특징 추출 → 정형 ML.

| 구분 | 문제 | 이 프로젝트 |
|---|---|---|
| 시계열 예측 | 과거로 다음 값을 맞춤 (ARIMA, LSTM) | 해당 없음 |
| 시계열 분류 | 시계열 전체를 보고 라벨 판정 | **해당** |

## 시계열 분류 4방법 (원문 2.5)
| 접근 | 개념 | 진동 관점 |
|---|---|---|
| ① 특징 추출 + ML (주력) | 통계 요약값 → RF 등 | 지금 파이프라인. tsfresh·catch22가 자동 추출 |
| ② 시퀀스 DL (RNN·LSTM·GRU) | 순차 기억 | 50,000점이면 장기 의존성 소실·연산 부담 → CNN-LSTM이나 압축 입력 |
| ③ 1D-CNN | 시간 축 커널로 지역 패턴 자동 추출 | 간헐 충격 포착에 탁월, 진동 DL 기본 구조 |
| ④ 거리 기반 (DTW) | 시간 축을 늘리고 줄여 유사도 | 정상 120개 기준 K-NN 이상감지 |

주의 (정리자)
- tsfresh는 수백 개라 150개에 과다. catch22(22개)는 비교 베이스라인으로 적당
- DTW는 길이² 계산(쌍당 약 25억 칸) → 윈도우 요약·포락선 같은 짧은 시퀀스에서만. 위상이 파일마다 달라 파형 정렬 자체가 의미 있는지 불확실
- 1D-CNN·LSTM은 150개로는 증강 필수, 발표 「개선 방향」 정도

## 정형 ML 고도화 사이클 (원문 3장)
- 단순 베이스라인 → 오류 분석(오답 노트) → 도메인 리서치·피처 추가 → 모델 고도화를 반복
- 초안: 로지스틱·결정트리로 버그·선형성 확인 → 고도화: 트리 앙상블(XGBoost, LightGBM, CatBoost) → 극대화: 성격이 다른 모델 스태킹·블렌딩
- PHM에서 바뀌는 점: 피처 엔지니어링 = 신호를 정형 데이터로 강제 변환·압축하는 과정 자체

## 모델 방법론 (원문)
| 방법 | 입력 | 방식 | 관점 |
|---|---|---|---|
| 트리 + Isolation Forest 앙상블 | 피처 표 | RF와 IF·OCSVM 확률을 Soft Voting | 현재 파이프라인과 바로 연결 |
| 오토인코더 | 피처 또는 신호 | 정상만 학습, 복원 오차 = 이상 점수, F2 임계값 | 비지도 |
| 1D-CNN | 원신호 | End-to-End | 과적합 위험, 증강 필수 |
| 2D-CNN | 스펙트로그램·스캘로그램 | ResNet 등 | PHM에서 높은 성능 보고 추세 (원문). Sai 2023 참고 |
| 이상감지 | 피처 표 | Isolation Forest, One-Class SVM, Mahalanobis, Autoencoder | 정상 군집 이탈 탐지 |

## 후보 모델: 각각 다른 질문을 검증 (원문)
| 모델 | 확인할 질문 | 우선순위 |
|---|---|---|
| TabPFN | 현재 특징의 정보를 ML이 충분히 쓰고 있나 | 높음 |
| MiniROCKET | 수작업 특징이 놓친 시계열 패턴이 있나. 다른 고장을 찾나 | 높음 |
| Elastic-Net 로지스틱 | 어떤 특징이 반복 선택되나, 복잡한 모델이 필요한가 | 높음 (기준) |
| Extra Trees | 무작위성을 늘리면 RF보다 안정적인가 | 중간 |
| GPC | 저차원에서 매끄러운 비선형 경계가 도움 되나 | 낮음 |

**최소 실험 구성 (원문)**
| 실험 | 입력 | 모델 | 얻을 정보 |
|---|---|---|---|
| ① | 같은 특징 세트 | LR·RBF-SVM·Extra Trees·TabPFN | 모델 변경 효과 |
| ② | 평균 제거 원신호 | MiniROCKET + Ridge | 자동 시계열 특징 효과 |
| ③ | 최대 진폭 정규화 적용/미적용 | 유력 모델만 | 진폭 정보 보존 효과 |

원문 표현 정정 (정리자)
- MiniROCKET "과적합 없이"는 잘못. 역전파가 없어도 과적합 가능
- TabPFN "1,000개 미만·100개 특징 이하"는 버전 공통 제한이 아님 → 버전 명시
- 분류에는 ElasticNet 회귀가 아니라 Elastic-Net 규제 **로지스틱** 회귀
- GPC 확률을 바로 신뢰도로 해석하면 안 됨

## 실전 포인트 (원문)
| 포인트 | 내용 |
|---|---|
| RobustScaler | 고장의 Peak·첨도·TKEO 극단치에 StandardScaler가 왜곡됨 → 중앙값·IQR 기반, 폴드 안에서 fit |
| 피처 압축 후 RBF-SVM / TabPFN | 폴드 안 MWU·MI 상위 12–15개 → RBF-SVM(`class_weight='balanced'`) |
| 임계값 F2 튜닝 | 기본값(0.5, 0.0) 금지 → [[08_평가_임계값]] |

주의 (정리자)
- RobustScaler fit 범위: 정상+고장 vs 정상만(One-Class) 비교 (D8)
- 앙상블: RF 확률과 IF 점수는 척도가 달라 정규화 후 Soft Voting
- 오토인코더는 정상만 학습해도 고장 30개를 F2 임계값 튜닝에 쓸 수 있음

## 확인 질문
1. 같은 피처로 선형 모델과 비선형 모델의 점수가 같다면 무엇이 병목이라고 볼 수 있는가
2. 트리와 L1 로지스틱이 서로 다른 고장을 놓친다면 앙상블에서 무엇을 기대할 수 있는가
3. One-Class 경로에서 고장 30개는 어디에 쓰는가
