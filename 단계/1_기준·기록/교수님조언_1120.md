# 교수님 조언 (2026-11-20)

## 사실 (교수님 말씀)
1. 피처를 너무 많이 뽑으면 고장이 확실한 피처여도 과적합될 수 있다.
2. 모델 파이프라인을 만드는 것도 좋은 방법이다.
   - 3개 군집으로 나눈 뒤, 군집마다 가장 좋은 모델을 고르고 피처를 뽑아 앙상블하는 방법도 있다.
   - train · val · test 성격이 다를 수 있고, 세 데이터에서 정상/고장이 나뉘는 집단이 3개일 수도 있기 때문이다.
3. 하이퍼파라미터 조정은 라벨이 없는 val · test로 해도 된다.
   - 텐션암 도메인 지식은 그렇게까지 중요하지 않다.
   - 순서: 데이터만 보고 구분 → 그다음 도메인으로 확인.

## 우리 데이터에 적용 (11-20 논의, 아직 실행 전)
### 1) 피처 과적합
- 고장이 30개뿐이라 피처 수보다 고장 개수가 한계. ext150은 VIF 전부 > 10, |ρ| ≥ 0.8에서 49 묶음 ([4-3](../4_피처/base/4-3_1116_팀원피처·중복지도/4-3_팀원피처·중복지도.md)) → 독립 정보는 약 50개.
- 줄이는 방법 후보
  - 묶음당 대표 1개 (라벨 없이 상관만으로 선택)
  - 물리가설(H1, H2′)에 연결된 피처만 유지
  - 확실한 고장 징후는 모델 대신 규칙으로 (학습 파라미터가 거의 없어 과적합 위험 작음)
  - 정규화 강화, 피처 선택도 중첩 CV 폴드 안에서
- 평가는 같은 중첩 CV F₂로 비교 (CLAUDE.md 원칙 1·3).

### 2) 군집 → 군집별 모델 → 앙상블
- 고장 30개를 3개로 나누면 군집당 약 10개 → 군집별 학습은 과적합 위험.
- 현재 구조(AE + ET + 규칙)는 이미 고장 유형별 전문가의 OR 결합. 새로 볼 것은 **정상을 군집으로 나눠 군집별 AE**.
- 군집 수가 데이터에 실제로 3개인지 먼저 확인해야 한다 (아직 모름).

### 3) 라벨 없는 val · test 활용
- 현재 규칙("val을 보고 문턱·구성을 고치지 않는다", 00_NOW · 결정.md)과 충돌. 제안: 구분을 라벨 유무로 바꾼다.
  - 허용: val · test 신호 분포 확인, 군집, 점수 분포를 보고 문턱·하이퍼파라미터 조정
  - 금지: 라벨이나 F2 점수를 본 뒤 고치는 것 (val 라벨은 어차피 없음)
- 후보 작업
  - adversarial validation (train vs val 구분 AUC; 0.5면 같은 분포)
  - val의 AE 재구성 오차 · 점수 분포 확인 (train 고장 비율 20% = 30/150과 비교, 문턱 1.0 점검)
  - 규칙 문턱(ζ, fit, 5.5–7.75 kHz)이 val에서 오경보를 내는지 확인
- "데이터로 구분 → 도메인으로 확인" 순서는 물리가설 먼저 세우는 현재 순서와 반대. 데이터에서 먼저 보이는 것에 가설을 나중에 붙이는 방식으로 이해.
