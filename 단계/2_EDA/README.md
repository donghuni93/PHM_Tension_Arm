# 2단계 탐색적 데이터 분석

상태: 1차 정리 완료 (11-16). 최종 구성(EXP-025)의 규칙 두 개가 모두 여기 EDA에서 나왔다

## 목적
라벨을 손으로 대역 고르는 데 쓰지 않으면서, 정상과 고장 신호가 어떻게 다른지 눈으로 이해한다. 물리가설(H1–H6)과 그림을 하나씩 맞춰 본다.

## 폴더 구조 (11-16 정리)
5단계 실험의 `유의미/·기각/`처럼 EDA 조각도 결과의 쓰임으로 나눈다.

```
2_EDA/
├─ README.md          이 파일 (조각 목록 · 분류 기준)
├─ 2-4_EDA뷰어/        도구: 150개 파일 시간·주파수 특징 한 화면 (VS Code 태스크 "EDA 뷰어 서버 켜기")
├─ 유의미/             최종 모델·결정에 들어간 발견, 남은 오류를 설명하는 발견 → 발표 핵심 근거
└─ 참고/               개관, 기각·수정된 가설, 효과 없음 → 왜 그 길로 안 갔는지의 근거
```

**분류 기준**
- **유의미** = ① 최종 구성(EXP-025)의 규칙·입력의 근거이거나 ② 남은 오류(놓침·오경보)를 설명해 판정표 관찰 열·6단계 오류 분석에 쓰였다
- **참고** = 데이터 개관이거나, 가설이 기각·수정됐거나, 모델에 넣었더니 효과가 없었다. 지우지 않고 "왜 안 했나"의 근거로 둔다
- 진행 중인 새 조각은 `2_EDA/` 바로 아래에 만들고, 결론이 나면 `유의미/` 또는 `참고/`로 옮긴다(5단계 `스크리닝/`과 같은 방식). 번호는 이어서(다음 2-17)

## 진행 방식 (11-13 사용자 결정)
- 2단계 EDA와 3단계 전처리를 이어서, 데이터를 뜯어보는 한 흐름으로 진행한다
- 조각 단위: 그림·해석 → 사용자 확인 → 다음. **조각 하나 = 번호 붙은 폴더 하나** (`2-n_MMDD_이름/` 안에 해석 md · 코드(`# %%` 셀 .py 또는 노트북) · `figs/`)
- 코드의 루트 찾기는 `src/`가 있는 상위 폴더를 거슬러 찾는 방식을 쓴다(폴더를 옮겨도 안 깨짐). 예전 조각 일부는 고정 깊이(`"..", "..", "..", ".."`)
- 라벨을 보고 대역·주파수를 고르지 않는다는 원칙은 그대로 (결정 "대역"). 그림을 본 뒤 정한 정의는 "사후"로 표시한다

## 해석과 결정
- 회색지대는 경계 모양이 아니라 **정보 부족** 문제였다 → EDA에서 물리적으로 다른 축(8.3 kHz 모드 폭, 유격 반복)을 찾은 것이 점수를 올렸다 (0.857 → 0.942)
- 고장은 한 덩어리가 아니라 정상 둘레에 흩어진다(고장끼리 거리 22.8 > 고장–정상 18.5) → "정상에서 얼마나 벗어났나"를 재는 구조가 맞다
- 결정은 [단계/1_기준·기록/결정.md](../1_기준·기록/결정.md)
