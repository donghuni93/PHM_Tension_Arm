## val 공개일(11/19) 절차
1. val 파일을 `data/val/`에 저장한다 (`val_001.csv` … `val_040.csv`). 제출 양식 CSV는 val 폴더 밖(`data/` 바로 아래)에 저장한다. val 폴더 안의 CSV는 모두 신호로 읽는다.
2. 예측을 실행한다. 학습은 다시 하지 않는다.
   ```
   conda run -n qe-phm python "단계/7_최종·제출/2_예측.py" data/val submission_val_9조.csv data/제출양식.csv
   ```
   - 세 번째 인자(제출 양식)를 생략하면 `file,label` 두 열로 저장된다. 양식이 공개되면 반드시 지정한다.
   - 머리글 한 줄·BOM·숨김 파일(`__MACOSX`)은 자동으로 처리한다. 신호가 1열이 아니거나 길이가 50,000점이 아니면 오류가 발생하며, 이 경우 `src/data.py` `load_folder`의 읽기 방식을 먼저 수정한다.
   - 양식의 열이 3개 이상이고 라벨 열을 자동으로 정하지 못하면 오류가 발생한다. `src/final.py` `write_submission(label_col=…)`로 지정한다.
   - 저장된 모델(`final_model.joblib`)은 학습한 환경(`qe-phm`, scikit-learn 1.9.1)에서만 읽는다. 다른 PC에서는 `1_학습.py`를 먼저 실행한다(약 5분, 같은 seed이므로 같은 모델).
3. `출력/요약_submission_val_9조.txt`에서 다음을 확인한다.
   - 고장 판정 비율. 학습 데이터는 20%였다. 50%를 넘거나 0에 가까우면 val 신호의 형식·단위가 학습과 다른지 확인한다.
   - 규칙으로 고장이 된 파일(8.3 kHz 스펙트럼 · 8.3 kHz 공진 · 유격 반복). 정답 공개 후 규칙이 켜진 정상이 있었는지 확인한다.
   - 본체 모드 내림으로 정상이 된 파일과, 내림 문턱 20% 이내인데 고장 판정된 파일. 내리는 규칙이라 틀리면 미탐이다.
   - 경계 파일. 임계값 seed에 따라 판정이 달라지는 파일이며 오류 가능성이 가장 높다.
   - 규칙 문턱 20% 이내인데 켜지지 않은 파일. 규칙의 문턱 여유(14–19%)를 val에서 확인하는 근거가 된다.
   - 관찰 열 2개(주기 잠금 문턱 이상, 큰 타격 1개인데 고장 판정). 판정에 사용하지 않았으나 EXP-030에서 제외한 장치의 val 근거가 된다.
4. 제출 파일 확정은 사용자 승인 사항이다 (CLAUDE.md 승인 규칙).

conda가 PATH에 없는 PC에서는 전체 경로로 실행한다. 예: `& "C:\Users\dongh\anaconda3\Scripts\conda.exe" run -n qe-phm python "단계/7_최종·제출/2_예측.py" …`


## val 점수 해석 (단계/1_기준·기록/결정.md 'val 점수')
- val은 40개 표본 하나다. 같은 모델이어도 표본에 따라 F2가 약 ±0.09(sd) 변동한다 (단계/1_기준·기록/결정.md 'val 점수' 항목).
- val 점수를 보고 문턱·구성을 변경하지 않는다. 변경하면 val이 학습 데이터의 일부가 되어 test 점수의 예측값으로 쓸 수 없다.
- val 점수가 0.80 미만이면 원인을 근거표에서 분류한다: 규칙의 오경보, 경계 파일, 학습에 없던 유형의 고장. 조치는 원인 기록까지이며 구성 변경은 사용자 결정으로 둔다.
