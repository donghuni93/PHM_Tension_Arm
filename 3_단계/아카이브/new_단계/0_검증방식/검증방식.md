# 검증방식 (new_단계) — 충격 이벤트 5피처 + 얕은 ExtraTrees

기존 검증 방식(2026-11-25, `3_단계/1_기준·기록/결정.md` "평가")을 이번 파이프라인에 맞춰 고친 기준이다. 평가 코드는 `src/evaluate.py`를 그대로 쓴다(`quick_cv` · `nested_cv`).
이 문서와 다른 문서가 다르면 이 문서가 new_단계의 기준이다. 라벨을 본 선택은 모두 표시한다.

## 1. 과제와 평가 (기존 유지)
- 데이터: Train 150(정상 120 · 고장 30), Val 40(라벨 비공개), Test 40(11/27 공개).
- 지표: **F2**(재현율 중시, 미탐 1건 ≈ 오경보 4건). 재현율 ↑ · 오경보율 ↓ 가 목표.
- val · test의 고장 비율은 비공개 → 비율 맞추기 튜닝 금지.
- **val = 라벨 없는 분포 · 정상 작동 확인용만.** 임계값 · 피처 · 대역을 val에 맞춰 고치지 않는다.
- **test = 최종 예측 1회만.** 제출 파일 확정은 사용자 승인 후.
- 마감: val 제출 11/26 23:59, test · PPTX 11/30 23:59.

## 2. 모델과 피처 전제 (기존 J / 결합 모델 대체)
**피처 5개 (크기 무관 세트)**

| # | 이름 | 정의 |
|---|---|---|
| 1 | `cnt_events_low_off` | 1.6–4.5 kHz 대표 울림 이벤트 수. 5.5 kHz 상한은 폴드 내 규칙으로 비교 가능 |
| 2 | `cnt_events_high_off` | 8.0–11.0 kHz 대표 울림 이벤트 수 |
| 3 | `ratio_off_events` | `(low_off + high_off) / (cnt_events_total + 1)` |
| 4 | `cnt_events_total` | 1.0–11.0 kHz 전체 병합 이벤트 수 |
| 5 | `off_max_clamped_amp` | off 이벤트의 `포락선 / max(100 ms 바탕, b_floor)` 최댓값 |

**모델**: 얕은 `ExtraTrees` — `max_depth=3~4`, `min_samples_leaf=3~5`, `class_weight='balanced'`. 스케일러 없음. 150개 소표본의 과적합을 막는 제약이다.

## 3. 기존 방식에서 바뀐 규칙
### 3-1. 이상치 정상 3개(N059 · N065 · N116) 학습 제외 보류
- 이번 단계는 `ExcludeTrain`을 쓰지 않고 **Train 150개 전체를 학습 · 평가**한다(기존 CLAUDE.md 원칙 5와 다름. 기존 문서는 그대로 둔다).
- 이상치 처리는 오류 분석 표를 본 뒤 후속 실험에서 다룬다. 후속에서 빼면 "CV 오류를 본 뒤의 사후 선택"으로 표시한다.
- 오류 분석 표에서 N059 · N065 · N116의 오경보 횟수를 따로 적는다.

### 3-2. 폴드 안 누수 차단
- **`b_floor`**(바탕 중앙값 하위 15% 또는 20%)는 **각 학습 폴드 안에서만 계산**해 검증 폴드에 적용한다. Train 전체에서 한 번에 계산하지 않는다.
  - `nested_cv`는 미리 만든 피처 행렬 `F`를 받는다. `b_floor`가 들어간 피처(`off_max_clamped_amp`)는 `F`에 최종값을 넣을 수 없으므로, 파일별 중간값(이벤트 포락선 · 100 ms 바탕)을 `F`로 두고 **`fit`에서 `b_floor`를 계산해 피처를 만드는 래퍼 모델**을 `make_model`로 넘긴다. 안쪽 CV에서도 같은 방식이다.
  - 4.5 vs 5.5 kHz, `b_floor` 15 vs 20 % 같은 후보 선택도 폴드 안에서 한다. 전체 라벨로 고른 값은 `[사후 값]`이다.
- **DC 오프셋 세션 묶음(097 · 101 · 120)**: 같은 그룹으로 묶어 `groups`에 같은 번호를 준다(`StratifiedGroupKFold`가 한 폴드에 몰아 넣는다). 평균 −1 g 파일은 116도 있다(`00_NOW.md`). 116도 같은 세션인지 확인 후 묶는다.
- 그 밖의 폴드 안 fit: 임계값(안쪽 OOF F2 최대), 대역 · 상한 선택, 모델.

### 3-3. 8.3 kHz 규칙 분리와 `[사후 값]` 표기
- **기본 모델 = ExtraTrees 단독**으로 평가한다.
- `ExtraTrees OR 8.3 kHz 규칙`(후처리 결합)은 **별도 비교군**이다. 규칙의 문턱은 라벨을 본 뒤 정한 값이라, 이 결합 점수에는 항상 **`[사후 값]`** 태그를 붙이고 기본 점수와 섞어 보고하지 않는다.
- 규칙이 올린 점수 = 규칙이 고친 고장 파일 수 + 규칙이 켠 정상 수로 풀어서 적는다.

## 4. 2단계 검증 절차 (`src/evaluate.py` 기준)
### 1단계 탐색 — `quick_cv`
- 파일 단위 5-fold OOF, **PR-AUC**(주) · ROC-AUC. 임계값을 고르지 않는다(같은 fold로 임계값을 고르면 F2가 +0.03~0.045 부풀고 순위가 뒤집힌다).
- 오류 분석 표와 함께 후보(`b_floor` 하한 비율, 4.5 vs 5.5 kHz 등)를 **1~2개로 줄인다.** 점수만 보고 피처를 쌓지 않는다.

### 2단계 정식 확인 — `nested_cv`, `QE_FULL=1`
- 바깥 5 × 안쪽 4 중첩 CV, seed 5 · ET 300. **F2 ± sd · 재현율 · 오경보율**을 확정한다(`Experiment.record`가 고장 10 · 40 %에서의 F2도 기록).
- 임계값은 안쪽 OOF에서 F2 최대(동점이면 낮은 쪽), 바깥 학습 전체로 재학습해 바깥 테스트를 예측한다.
- **차이가 full sd(약 0.010) 안이면 더 단순한 모델을 채택한다.** 이 sd는 기존 J 계열 값이므로, 새 모델의 seed별 sd를 먼저 구해 쓴다.
- 기본 모드(quick: seed 2 · ET 100)는 후보를 빨리 거를 때만 쓰고, quick sd는 믿지 않는다. quick과 full 수치를 섞어 비교하지 않는다.
- ET 설정(`max_depth` · `min_samples_leaf`)은 `evaluate.ET_N`(나무 수)과 별개로 모델 래퍼에서 지정한다.

### 오류 분석 표 (매 실험)
우리 판단(= 정답 라벨) vs 모델 판단(seed n번 중 몇 번, n = quick 2 · full 5)을 가로로 놓고 자주 놓친 고장 · 오경보 파일을 적는다. 사각지대로 알려진 고장(023 · 030)과 오경보 정상 18개(2-5)의 변화를 따로 본다.

## 5. 무라벨 Val(40개) 점검 — 3-Gate
라벨 없이 **통과 / 이상**만 판단한다. 통과해도 성능 보증이 아니다.

1. **분포 이동**: Train 150 vs Val 40의 5개 피처 중앙값 · IQR을 비교한다. 큰 차이가 나면 val 라벨이 없어도 그 피처를 의심한다.
2. **양성 비율 상식**: 최종 모델이 낸 Val 예측 양성 비율이 Train 고장 비율(20 %)에서 크게 벗어나지 않는지 본다. 값이 이상하면 문턱 · 피처를 val에 맞춰 고치지 않고 원인만 기록한다.
3. **지속음 이상치 `val_001`**: 정상으로 판정되는지 확인한다.
