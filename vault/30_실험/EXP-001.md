# EXP-001 베이스라인: core 피처 13개 × 로지스틱 회귀 / RBF-SVM

## 목적 (무엇을 확인하려 했나)
- 노션 도메인 지식으로 고른 core 피처 13개가 정직한 평가에서 바닥 점수(전부 고장 0.556)를 넘는가
- 단순 모델과 비선형 모델의 차이, 누수가 점수를 얼마나 부풀리는가

## 설정
- 데이터: `data/TeamProject_train_변경/` 정상 120, 고장 30
- 특징셋: [[features]] core 13개 (평균 제거, MA 미적용, 대역 0–2k/2k–5k/5k–12.5k)
- 모델: `RobustScaler` → 로지스틱 회귀(`class_weight='balanced'`, 기본 C) / RBF-SVM(`class_weight='balanced'`, 기본 C·gamma)
- 검증 방식: 중첩 CV. 바깥 StratifiedGroupKFold 5-fold(그룹 = 파일) × 안쪽 4-fold, seed 0–4
- 임계값: 안쪽 OOF 점수에서 F₂ 최대(같으면 가장 낮은 값), 바깥 fold에 적용
- 코드: `src/evaluate.py`, `notebooks/04_베이스라인.ipynb` (점수는 c76e767, 오류 분석 셀은 다음 커밋)

## 결과
| 지표 | 로지스틱 회귀 | RBF-SVM |
|---|---|---|
| CV F2 (평균 ± 표준편차) | 0.608 ± 0.055 | 0.606 ± 0.026 |
| 재현율(recall) | 0.753 | 0.773 |
| 정밀도(precision) | 0.348 | 0.326 |
| 놓친 고장 (30개 중, 평균) | 7.4 | 6.8 |
| 오경보 (120개 중, 평균) | 43.4 | 48.0 |
| 누수 버전 F2 (같은 OOF로 임계값) | 0.669 | 0.656 |

- seed별 F2: 로지스틱 0.650 / 0.505 / 0.653 / 0.638 / 0.596, SVM 0.619 / 0.619 / 0.591 / 0.638 / 0.565
- 바닥 점수: 전부 고장 0.556, RMS 관리도 0.080

## 오류 분석 (놓친 고장, 오경보)
- 두 모델 모두 seed 5개 중 3번 이상 놓친 고장: abn_002, abn_022, abn_023, abn_029
- 정상 120개 대비 백분위

- 잘 잡힌 고장은 "크고 고주파 쪽으로 쏠린" 신호(RMS·Peak·TKEO 상위 5%, 저주파 비율 하위 7%)
- 놓친 고장 4개는 모든 피처가 정상 분포 한가운데(대부분 백분위 20–85). abn_002는 오히려 정상보다 조용한 쪽, abn_022·023은 고주파 비율이 낮아 잡힌 고장과 반대 방향
- 오경보: 로지스틱 39개, SVM 49개 정상 파일이 seed 3번 이상 오경보 (목록은 노트북 2절)

## 결론
- 바닥 점수보다 +0.05. core 13개는 "크고 시끄러운" 고장만 구분한다
- 로지스틱 회귀 ≈ RBF-SVM → 병목은 모델이 아니라 피처
- 누수 버전은 +0.05–0.06 부풀려짐. 베이스라인과 바닥 점수의 차이와 같은 크기라, 중첩 CV 없이는 개선을 잘못 판단할 수 있음
- 피처 간 상관(정상만, [[01_코드지도]] 03 노트북): T15·B01·B03·F01이 한 묶음(|r| 0.86–0.98), T02·T16(0.90)
